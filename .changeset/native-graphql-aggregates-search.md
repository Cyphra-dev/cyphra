Native API aggregates and search (#246): `<model>Aggregate` (`_count` / `_sum` / `_avg` / `_min` / `_max` typed per field, `where`, and `orderBy` / `skip` / `take` for a window) and `<model>GroupBy` (`by: { fields, <toOneRelation> }`, `having` on keys and aggregates, `orderBy` by key or aggregate, only the selected aggregates computed); `<model>Search` on `@@fulltext` indexes (`index`, `query`, `mode`, `where`, `minScore`, `skip`, `take`) and `<model>FindSimilar` on `@vectorIndex` fields (`field`, `vector`, `k`, `where`, `minScore`), with `_score` on the hits; `<union>Search` / `<union>FindSimilar` over the members' indexes (reciprocal rank fusion, `indexes` / `fields`, `_on` filters, `rrfK`), with `_scores: [IndexScore!]`. `aggregate`, `groupBy` and `search` are read operations (on by default); `findSimilar` is in the new `traverse` operation group, off by default. Read rules hide nodes from counts, groups and hits, row-dependent field rules from aggregated values, and a field a context-only rule denies cannot be aggregated or grouped on (`FORBIDDEN`). `_score` / `_scores` outside a search, and a group field not listed in `by`, are `BAD_USER_INPUT`. Every model now prints its aggregate and groupBy types: regenerate a committed contract with `cyphra graphql print`.
