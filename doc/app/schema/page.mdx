# Schema DSL

Your graph lives in one file, `schema.cyphra`: its nodes, the relationships between them and the
decorators that become Neo4j constraints and indexes. The CLI, the typed client and migrations all
read it.

```cyphra
node User {
  id    String @id @default(cuid())
  email String @unique
  name  String @index
}

node Post {
  id     String @id
  title  String
  author User? @relationship(type: "AUTHORED", direction: IN)
}

relationship Follows {
  type "FOLLOWS"
  from User
  to User
  since     DateTime @index
  requestId String   @unique
}
```

## Scalar types

`String`, `Int`, `Float`, `Boolean`, `DateTime`, `Date`. Append `?` for optional
(`String?`) or `[]` for a list (`String[]`). Lists are never optional; an absent list reads as `[]`.

## Defaults

`@default(cuid())`, `@default(uuid())` (String), `@default(now())` (DateTime / Date), or a
literal matching the field type: `@default("draft")`, `@default(0)`, `@default(1.5)`, `@default(true)`.
The [typed client](/client) applies them on create.

## Relationships

`posts Post[] @relationship(type: "AUTHORED", direction: OUT)`. `direction` defaults to
`OUT`. If a `relationship { … }` model has the same type and endpoints, its properties type the edge
(`$edge` in the client).

## Decorators

`@id`, `@unique`, `@index` (Neo4j 5+ **range** index: on nodes via `(n:Label)`, on rich relationships via `()-[r:TYPE]-()`), `@default(…)`, `@relationship(…)`. On **nodes**, you cannot combine `@index` with `@id` or `@unique` on the same field (those constraints already imply an index). On **relationship** models, `@unique` maps to a **relationship property uniqueness** constraint (Neo4j **5.7+**); `@id` is not allowed on relationship fields.

## Programmatic API

`parseSchema`, `parseSchemaFile` and `printSchemaDocument` are exported from `cyphra` (or
`@cyphra/schema`). `parseSchemaFile(path)` loads a UTF-8 `.cyphra` file from disk (Node.js).

The parser produces an AST used by `cyphra push`, `cyphra generate`, and programmatic APIs. Use `printSchemaDocument` from `@cyphra/schema` (or **`cyphra schema print`**) to emit a canonical `.cyphra` text for diffs and reviews—comments are not preserved.
