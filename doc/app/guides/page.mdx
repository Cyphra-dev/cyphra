# Guides

How to use Neo4j from the TypeScript framework you already have, with Cyphra's
[typed client](/client). Each guide was run end to end on a fresh project against Neo4j 5, and says
which versions it was tested with.

The [tRPC guide](/guides/trpc) builds a typed API: the zod schemas Cyphra generates from
`schema.cyphra` validate procedure input, and the types reach React without a type written by hand.

The [GraphRAG guide](/guides/graphrag) builds retrieval for a question-answering app: vector and
full-text search over document chunks, then expansion through the chunks' entities.

[Migrate from @neo4j/graphql](/guides/migrate-from-neo4j-graphql) is a checklist to serve an
existing `@neo4j/graphql` 7 API with `@cyphra/graphql`, with the same type definitions and frontend
queries, and to add migrations and the typed client on the same graph.

## What every framework guide has in common

- **One client per process.** `createClient` opens a Neo4j driver with a connection pool. Create
  it once and share it; each guide shows the idiomatic place for that in its framework.
- **Credentials in the environment.** `NEO4J_URI`, `NEO4J_USERNAME` and `NEO4J_PASSWORD`, written
  for you by `cyphra dev` locally, set by you in production.
- **Server side only.** The driver and the credentials never reach a browser bundle.
- **Migrations before the app.** `cyphra migrate deploy` applies pending
  [migrations](/migrations) before new code starts using the schema.
- **Neo4j 5.6 or later**, for example Neo4j Aura, [Cyphra Cloud](/cloud) or the `neo4j:5` Docker
  image that `cyphra dev` starts.
