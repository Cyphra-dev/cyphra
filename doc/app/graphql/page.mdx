# GraphQL

**`@cyphra/graphql`** serves the API that `@neo4j/graphql` 7.6 generates from your type definitions:
the same types, fields, filters, sorting, pagination and results. You keep your `typeDefs` and your
frontend queries, and the API runs on the Cyphra runtime.

<Callout type="warning">
  This is an early release. The full v7 schema is generated, and queries (aggregations included) and
  mutations work. Authorization and `@cypher` fields are in the schema but return a `Not implemented
  yet` error for now. See [what works today](#what-works-today).
</Callout>

## Install

```bash
npm i @cyphra/graphql graphql neo4j-driver
```

It needs Neo4j 5.23 or later (like `@neo4j/graphql` 7) and `graphql` 16.

## Create the schema

`compat.v7.makeSchema` takes the type definitions you pass to `new Neo4jGraphQL(...)` and returns a
`GraphQLSchema` with its resolvers. Any GraphQL server can serve it.

```ts filename="lib/graphql.ts"
import { compat } from "@cyphra/graphql";
import neo4j from "neo4j-driver";
import { typeDefs } from "./typeDefs";

const driver = neo4j.driver(
  process.env.NEO4J_URI!,
  neo4j.auth.basic(process.env.NEO4J_USERNAME!, process.env.NEO4J_PASSWORD!),
);

// Before: await new Neo4jGraphQL({ typeDefs, driver }).getSchema()
export const schema = compat.v7.makeSchema({ typeDefs, driver });
```

| Option     | Description                                                                 |
| ---------- | --------------------------------------------------------------------------- |
| `typeDefs` | Your v7 type definitions (`@node`, `@relationship`, …), as a string.        |
| `driver`   | A `neo4j-driver` driver.                                                    |
| `client`   | A `CyphraClient`, instead of `driver`, to share the connection of your app. |
| `database` | Database name used with `driver`. Default: the default database.            |
| `debug`    | Log each generated Cypher statement and its parameter names (not values).   |

`makeSchema` throws an `UnsupportedTypeDefsError` when the type definitions use something it cannot
serve yet (interfaces, unions, `Point`, `Duration`, custom scalars, …). It never serves an API that
differs from v7 without telling you.

## Serve it from a Next.js route

With GraphQL Yoga:

```ts filename="app/api/graphql/route.ts"
import { createYoga } from "graphql-yoga";
import { schema } from "@/lib/graphql";

const { handleRequest } = createYoga({
  schema,
  graphqlEndpoint: "/api/graphql",
  fetchAPI: { Response },
});

export { handleRequest as GET, handleRequest as POST, handleRequest as OPTIONS };
```

With Apollo Server:

```ts filename="app/api/graphql/route.ts"
import { ApolloServer } from "@apollo/server";
import { startServerAndCreateNextHandler } from "@as-integrations/next";
import type { NextRequest } from "next/server";
import { schema } from "@/lib/graphql";

const server = new ApolloServer({ schema });
const handler = startServerAndCreateNextHandler<NextRequest>(server);

export { handler as GET, handler as POST };
```

Queries written for `@neo4j/graphql` work as they are:

```graphql
query {
  movies(
    where: { actors: { some: { name: { eq: "Keanu Reeves" } } } }
    sort: [{ released: DESC }]
  ) {
    title
    actorsConnection(first: 2, sort: [{ edge: { screenTime: DESC } }]) {
      totalCount
      edges {
        cursor
        properties {
          roles
        }
        node {
          name
        }
      }
      pageInfo {
        hasNextPage
        endCursor
      }
    }
  }
}
```

Mutations written for `@neo4j/graphql` work as they are too, nested writes included:

```graphql
mutation {
  updateMovies(
    where: { title: { eq: "The Matrix" } }
    update: {
      released: { add: 1 }
      actors: [
        {
          connect: [{ where: { node: { name: { eq: "Al Pacino" } } }, edge: { roles: ["Cameo"] } }]
        }
        { disconnect: [{ where: { node: { name: { eq: "Laurence Fishburne" } } } }] }
      ]
    }
  ) {
    info {
      relationshipsCreated
      relationshipsDeleted
    }
    movies {
      title
      released
    }
  }
}
```

Each root field runs as one Cypher statement, in its own transaction (a read transaction for
queries, a write transaction for mutations). Values are always parameters, and labels, property
keys and relationship types come from your type definitions.

## What works today

Compatibility is checked by a suite of 5 apps and 48 operations. Its expected results come from the
real `@neo4j/graphql` 7.6.8. Today 38 of its 53 checks pass: the printed schema of all 5 apps, and
the 33 operations (queries, aggregations and mutations) that use no authorization or `@cypher`
field. The full report is [`compat/graphql/REPORT.md`](https://github.com/Cyphra-dev/cyphra/blob/main/compat/graphql/REPORT.md).

| Feature                                                                                                                                       | Status                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Generated schema: queries, connections, every `where` / `sort` / mutation input, aggregate types, deprecated `field_OPERATOR` fields          | Works: the printed SDL is identical to v7                       |
| List queries: `movies(where, sort, limit, offset)`, pluralization like v7, `@plural`                                                          | Works                                                           |
| Filters on `String`, `ID`, `Int`, `Float`, `BigInt`, `Boolean`, `Date`, `DateTime`, enums and lists, with `AND` / `OR` / `NOT`                | Works                                                           |
| Relationship filters `some` / `all` / `none` / `single`, connection filters on `node` and `edge`                                              | Works                                                           |
| Connections: `totalCount`, `pageInfo`, cursors with `first` / `after`, nested connections with edge `properties`, sort and filter on edges    | Works                                                           |
| Nested relationship fields with `where`, `sort`, `limit`, `offset`                                                                            | Works                                                           |
| Aggregations: `aggregate { count, node, edge }` on root and nested connections, aggregation filters (`aggregate` and deprecated `xAggregate`) | Works                                                           |
| Mutations: `create`, `update`, `delete` with `info` counters, and the response selection                                                      | Works                                                           |
| Nested writes: `create`, `connect`, `disconnect`, `update`, `delete` (nested in each other), edge properties                                  | Works                                                           |
| Update operators: `set`, `add`, `subtract`, `multiply`, `divide`, `push`, `pop` and the deprecated `field_SET` / `field_INCREMENT` / …        | Works                                                           |
| `@id`, `@timestamp`, `@default`                                                                                                               | Works                                                           |
| `@authentication` / `@authorization`                                                                                                          | Not yet ([#74](https://github.com/Cyphra-dev/cyphra/issues/74)) |
| `@cypher` fields                                                                                                                              | Not yet ([#75](https://github.com/Cyphra-dev/cyphra/issues/75)) |

A type with `@authentication` or `@authorization` rules is never read or written without them: the
operation returns a `Not implemented yet` error instead of unfiltered data or an unchecked write.

### v7 behaviour you get as well

- `{ eq: null }` matches nodes where the property is missing.
- An empty filter in `some`, `none` or `single` (`actors: { some: {} }`) is ignored: it matches every
  node. `all` is not true for a node with no related nodes.
- A cursor is `base64("arrayconnection:<offset>")`. An invalid `after` cursor returns the first page.
- `BigInt` values are returned as strings, `Date` as `yyyy-mm-dd` and `DateTime` as ISO-8601 strings.
  BigInt aggregates are strings too, `average` included. An Int `average` is a Float.
- Aggregates ignore `first` / `after` but apply the connection `where`. `count.nodes` and `node`
  aggregates count each related node once. On an empty set, `count` and `sum` are `0` and the other
  aggregates are `null`. An aggregation filter that compares a `null` aggregate matches nothing, even
  under `NOT`.
  As in v7, `Date` inputs are read in the time zone of the process: run the server with `TZ=UTC`.

### Mutations, as in v7

- `connect` creates a relationship to every node that matches `where`. It is a `CREATE`, not a
  `MERGE`: connecting a pair that is already connected adds a second relationship, whether the
  mutations run one after the other or at the same time. To skip nodes that are already connected,
  filter them out in `where` (for example `movies: { none: { id: { eq: "…" } } }`); that filter
  does not lock, so two concurrent mutations can still both connect.
- In an update, the scalar operators run first, then each relationship field, element by element,
  in the order `update`, `create`, `connect`, `delete`, `disconnect`.
- `@id` fields get a UUID on create. `@timestamp` fields are set on create and on every update of
  the node, even an update without an `update` argument. On relationships they are set by nested
  `create` and nested `update`, not by `connect`.
- `add` or `subtract` on a missing value, an `Int` result beyond 32 bits, and `push` / `pop` on a
  missing list fail the mutation: nothing is written. v7 runs these checks with APOC; Cyphra does not
  need APOC, and the error message is the APOC message without its `Failed to invoke procedure`
  prefix.
- `info` counts the nodes and relationships the mutation created, the relationships it removed, and
  the distinct nodes it deleted with every relationship attached to them. It is computed in the
  statement, so it does not depend on driver result counters.
- The response of a mutation (`movies { … }`) is read after all of its writes. With several inputs
  in one `createMovies`, v7 can return a node as it was before a later input connected to it.

## Move the data model to Cyphra

The GraphQL API and the Cyphra ORM can work on the same graph. To get a `schema.cyphra` from the same
type definitions, run [`cyphra import graphql`](/cli#import-from-neo4jgraphql). In code,
`compat.v7.cyphraSchema(typeDefs)` returns the same conversion as a schema model, with the list of
what Cyphra models differently.
